TalentIQ Engine — Backend Reference

The skill knowledge graph

This is where it lives: backend/src/data/skillsRepository.json + services/skillsRepository.ts, read by the matching engine on every search. There's no browsing page for it in the product — it's infrastructure the agents reason with, not a screen HR clicks into. This page exists so the mechanism can be pointed at directly.

1

Skills have synonyms. "ML" and "Machine Learning" are the same skill — every alias resolves to one canonical name before anything gets compared.

2

Skills have neighbors. Each skill lists what's related to it — Product Roadmapping is adjacent to Requirement Gathering, Backlog Prioritization, and Go-To-Market Strategy.

3

Matching uses both. Missing a required skill isn't an automatic zero — holding something adjacent to it earns real, capped partial credit and a plain-English reason why.

How the credit is actually computed

services/matching.ts — scoreEmployeeForRole()

direct match weight × (0.85 + 0.15 × confidence)
adjacent match weight × 0.4 × confidence(adjacent skill) × min(1, level ÷ minLevel)
Why 0.4×. An adjacent skill is evidence of related capability, not proof of the required one — Product Roadmapping suggests someone can reason about requirements, it doesn't confirm they've run a stakeholder workshop. The multiplier keeps graph credit real without letting it counterfeit a direct match, and it's why Aditya still lands as a gap-tier "stretch match," not a false "ready."
